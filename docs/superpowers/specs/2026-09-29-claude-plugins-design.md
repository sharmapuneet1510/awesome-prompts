# Ship awesome-prompts as Claude Code plugins — Design

**Issue:** #53 (part of #68) · **Date:** 2026-09-29 · **Status:** Draft — awaiting review

## Problem

`python3 tools/exporter.py --target claude` writes files Claude Code does not
load:

- **Skills** are flat files (`.claude/skills/adr_skill.md`). Claude Code loads
  only `<name>/SKILL.md` directories.
- **Every exported file starts with an HTML comment**, not YAML front matter, so
  no `description` reaches Claude and no agent file registers.
- **`agent:function` has no mechanism behind it.** Typing `architect:analyse …`
  gives the model plain text to interpret.

So none of the 44 skills or 43 functions is ever loaded.

## Goal and success criteria

After `/plugin marketplace add sharmapuneet1510/awesome-prompts` and installing
the plugins:

1. `/architect:adr` and the other 42 functions appear in the `/` menu.
2. The 44 reference skills appear in Claude Code's skill list, with descriptions.
3. A test fails if any exported file lacks valid front matter.
4. `claude plugin validate --strict` passes for the marketplace and every plugin.

## Decisions (agreed 2026-09-29)

| Question | Decision |
|---|---|
| Plugin split | Five role plugins + one `engineering-skills` plugin, in one marketplace |
| Who may start a function | Only the user: every function has `disable-model-invocation: true` |
| This repo's `.claude/` | Delete the dead flat exports; register the repo's own marketplace in `.claude/settings.json` |
| Subagents | None in this issue; role agents ship as on-demand reference files |

## Layout

Generated by `tools/exporter.py --target claude` and committed, as `.claude/`
is today.

```text
.claude-plugin/marketplace.json            name "awesome-prompts"; 6 entries, sources "./plugins/<name>"
plugins/
  architect/  quality/  implementer/  orchestrator/  ba/
    .claude-plugin/plugin.json             name = function prefix → /architect:adr
    skills/<function>/SKILL.md             one per function
    reference/agent.md                     the role's agent file, front matter removed
    reference/rules.md                     instructions/master_instruction_set.md
  engineering-skills/
    .claude-plugin/plugin.json
    skills/<name>/SKILL.md                 44 reference skills
```

| Plugin | Source | Commands |
|---|---|---|
| `orchestrator` | `agents/orchestrator_agent.md` + `agents/orchestrator/functions/` | 10 |
| `architect` | `agents/architect_agent.md` + `agents/architect/functions/` | 9 |
| `implementer` | `agents/implementer_agent.md` + `agents/implementer/functions/` | 7 |
| `quality` | `agents/quality_agent.md` + `agents/quality/functions/` | 10 |
| `ba` | `agents/business_analyst_agent.md` + `agents/business_analyst/functions/` | 7 |
| `engineering-skills` | `skills/*_skill.md` | — (44 skills Claude loads when relevant) |

Plugin names are the function prefixes, because plugin components are
namespaced `<plugin>:<skill>`. Every `plugin.json` carries `name`, `version`
(from `pyproject.toml`), `description`, `author`, `repository`, `license`.

Agent modules (`agents/<role>/modules/*.md`) ship under `reference/modules/` in
their role plugin, since functions such as `orchestrator:ideate` use them.

## Content mapping

### Function → `skills/<function>/SKILL.md`

```yaml
---
name: adr
description: <source function front matter `description`>
argument-hint: <from the function's "## Inputs" code block, e.g. "jira=<KEY> [path=<dir>]">
disable-model-invocation: true
---
Role and rules: read ${CLAUDE_PLUGIN_ROOT}/reference/agent.md and
${CLAUDE_PLUGIN_ROOT}/reference/rules.md for the sections this function needs.

<function body, with links rewritten>
```

- `name` is the function slug (`batch-review` stays `batch-review`).
- `argument-hint` is omitted when the function has no Inputs block. Its source
  is the first line of that block with the `<prefix>:<fn>` stripped.
- `$ARGUMENTS` is not injected: the function bodies already describe their
  parameters, and the user's typed arguments reach Claude with the command.

### Reference skill → `engineering-skills/skills/<name>/SKILL.md`

```yaml
---
name: java-advanced                    # slug minus _skill, underscores → hyphens
description: <Quick Card "Use when" row>
---
<whole skill body, Quick Card first>
```

The Quick Card "Use when" row is under 30 words by rule, so the 44 descriptions
fit the always-loaded skill listing (about 1% of the context window). A skill
with no "Use when" row falls back to its front matter `description`, cut at
the first sentence.

### Links

Applied to every generated Markdown file:

| Link target | Becomes |
|---|---|
| Another exported skill (`skills/adr_skill.md`) | Plain text `engineering-skills:adr` skill |
| A file shipped in the same plugin | Relative path inside the plugin |
| Any other repo file (`docs/…`, `instructions/…`) | `https://github.com/sharmapuneet1510/awesome-prompts/blob/main/<path>` |
| Absolute URLs, anchors | Unchanged |

## Source changes

1. **Eight function files**, so all 43 dispatch-table functions are commands:
   - `agents/orchestrator/functions/{plan,context,build,pr,review,tradeoff,risk}.md`,
     moved from `agents/orchestrator_agent.md` (sections `### orchestrator:<fn>`,
     lines 946–1131). The agent file keeps a table linking to them.
   - `agents/business_analyst/functions/create.md`, delegating to `skills/ba_create_skill.md`.
   - Counts that `tests/nemesis/test_nemesis_registration.py` checks
     (`| Functions | N | agents/*/functions/*.md |`) move from 35 to 43.
2. **Exporter:** the `claude` target writes the plugin layout and marketplace.
   The other seven targets are unchanged.

## This repo's `.claude/`

- Delete `.claude/skills/`, `.claude/agents/`, `.claude/prompts/` and
  `.claude/.claude-export-manifest.json` (119 tracked files that never load). Keep
  `.claude/hooks/`.
- `.claude/settings.json` gains:
  ```json
  { "extraKnownMarketplaces": { "awesome-prompts": { "source": { "source": "directory", "path": "." } } } }
  ```
  How a relative `path` resolves in project settings isn't documented. The
  implementation verifies it with the real CLI and switches to
  `claude plugin marketplace add ./` instructions if it doesn't resolve.
  The exporter already merges its hook keys into existing settings rather than
  replacing them.
- README Quick start and `docs/01-workflows/14-export-to-platforms.md` switch to
  `/plugin marketplace add sharmapuneet1510/awesome-prompts` and
  `/plugin install <plugin>@awesome-prompts`.

## Verification

- **`tests/tools/test_plugin_export.py`**, exporting into a temporary directory:
  - every `SKILL.md` begins with `---` and its front matter parses as YAML;
  - `name` is kebab-case, ≤ 64 characters, unique within its plugin;
  - `description` is present and, with `when_to_use`, ≤ 1,536 characters;
  - all 43 function skills set `disable-model-invocation: true`; 44 reference skills exist;
  - each `plugin.json` parses and its `name` matches the plugin directory;
  - every marketplace entry's `source` exists and names a plugin with a manifest;
  - no relative link in `plugins/` points at a missing file.
- **Freshness:** the committed `plugins/` and `.claude-plugin/` equal a fresh
  export, byte for byte.
- **Official validator:** `claude plugin validate --strict` on the marketplace
  and each plugin. It runs in pytest when `claude` is on `PATH` (skipped
  otherwise) and in a CI step that installs the Claude Code CLI. If validate
  needs authentication in CI, it stays a local check and the PR says so.
- **Acceptance evidence:** `claude plugin details` lists each plugin's commands
  and token cost. The user confirms `/architect:adr` in the `/` menu after a
  real install — the one step that can't be observed from a test.
